# ZEN DIVE Manila — スクロールジャーニー実装指示書（scroll-driven diver journey）

対象ブランチ: `redesign/kinetic` から新ブランチ `redesign/journey` を切って作業すること。

## 0. ゴール

スクロールに完全連動して、一人のダイバーが「もうひとつの人生」を旅するページにする。
スクロール＝潜水。ページを下るほど深く潜り、新しい景色・魚・沈没船・バディ（仲間）に**出会っていき**、最後に浮上して「少し別の人」になって戻ってくる——ダイビングという人生の縮図を1ページで体験させる。

参考にした動き（X の動画2本）の要点:
- キャラクターが固定レイヤーに常駐し、スクロール量に scrub でひも付いて移動する
- 背景・出会うオブジェクトはシーンごとに横/縦からパララックスで流入する
- テキストはシーンの「章タイトル」として出会いのたびに現れて消える

## 1. コンセプトコピー（この方向で。最終選定は実装時に見た目と合わせて判断）

メインコンセプト: **「もうひとつの人生に、潜る。」**

シーン用コピー候補（下の台本で使用）:
- hero: 「地上のあなたを、置いていく。」
- 最初の呼吸: 「水中で吸う、最初のひと息。ここから、二人目のあなたが始まる。」
- サンゴ: 「地上では一生会えなかった色に、会う。」
- 群れ: 「一万匹の銀色が、あなたを通り過ぎていく。」
- 沈没船: 「時間が止まった場所に、あなたの時間だけが流れる。」
- バディ: 「ひとりで潜って、ふたりで帰ってくる。」
- 浮上: 「浮上したとき、あなたは少しだけ、別の人になっている。」

トーン規則: 既存サイトの明朝体・静けさ・「脳を手放す」系の文体を守る。絵文字・感嘆符は使わない。

## 2. アーキテクチャ（既存設計に乗せる。壊さない）

既存の資産（必ず読むこと）:
- `js/main.js` — Lenis ⇄ ScrollTrigger、**master depth**（ページ全体のスクロール進行が水深・カラーグレード・`#depthmeter` を駆動）が既にある。ジャーニーもこの master depth を単一の真実として使う。独自の進行管理を作らない。
- `js/ocean.js` — WebGL 水面/パーティクル。泡の発生レートをスクロール速度に連動させるフックを足す程度に留める。
- `index.html` — 各 `<section>` に `data-depth` あり。セクション順: hero → interlude → contrast → descent → silence → experience → marquee → gallery → offers → access → trust → cta。

新規に作るもの:
- `js/journey.js` — ジャーニー専用モジュール（main.js を肥大化させない）。`window.ZEN_DEPTH`（または main.js が公開する progress getter）を購読。
- 固定ステージ: `<div id="journeyStage" aria-hidden="true">` を `#ocean` キャンバスの上・コンテンツの下の z-index に置く（`position: fixed; inset: 0; pointer-events: none;`）。ダイバーと「出会い」レイヤーはすべてこの中。
- 新規 pinned シーン3つ（下の台本 S3/S4/S5）を既存セクションの間に挿入。それ以外の既存セクションは**レイアウトを変えず**、ステージ上の演出だけを重ねる。

## 3. ダイバーキャラ仕様

- インライン SVG で描く（外部画像不可）。写実ではなく、既存サイトのトーンに合わせた**線＋シルエット**（stroke 主体、フィン・タンク・マスク・泡が判別できる程度のミニマルさ）。
- パーツ分割: body / fins / bubbles-emitter / light(ライト用の円錐グラデ、S4 のみ点灯)。
- フィンキックは scroll と独立した CSS keyframes ループ（2s、rotate ±8°）。**移動だけ**が scroll 連動。
- 移動は GSAP MotionPathPlugin（CDN 追加可: gsap 3.12 系に合わせる）。パスの接線に応じて自動回転 `autoRotate: true`、ただし ±35° にクランプ（真下向きにしない）。
- 画面内の基本ポジションは中央やや左。シーンごとにパスで泳がせる（下表）。
- スクロール停止中は微小な浮遊（y ±6px, 3s ease-in-out infinite）。スクロール速度が速いときは泡の発生量を増やす（ocean.js のエミッタに velocity を渡す）。

## 4. シーン台本

master progress 0→1 を以下に割り当てる。「出会い」はすべて journeyStage 上のレイヤー。

| # | progress | 対応セクション | 深度表示 | 出会い・演出 | ダイバーの動き |
|---|----------|--------------|---------|------------|--------------|
| S0 | 0–.08 | hero（既存 hold-to-dive は維持） | 0m | 水面。既存のまま。ダイバーはまだ出さない | — |
| S1 | .08–.18 | interlude〜contrast | 3–5m | **最初の呼吸**。ダイバー初登場（水面から入水、泡の柱）。光条（god rays）を CSS gradient + blur で2本 | 画面上端から中央へ緩い S 字で降下 |
| S2 | .18–.32 | descent〜silence | 8–12m | **サンゴの庭**。SVG のサンゴ/イソギンチャク群が下端から視差流入（3レイヤー、速度差 0.4/0.7/1.0）。クマノミ3匹が右→左へ横切る。ウミガメが1匹、ダイバーの下をゆっくり交差 | 左→右へ水平移動しつつ緩降下 |
| S3 | .32–.44 | **新規 pinned セクション**（gallery の前に挿入、pin 200vh） | 18m | **群れとの遭遇**。イワシ玉: 楕円軌道の SVG 魚スプライト 40–60 匹を JS で複製し、位相をずらして回転。scrub でダイバーが玉の中心を通過し、通過時に群れが割れる（各魚にダイバーからの距離で反発オフセット） | 群れの中心をまっすぐ貫通 |
| S4 | .44–.58 | **新規 pinned セクション**（200vh） | 25m | **沈没船**。船のシルエット（大きな SVG、mask で霧の中から reveal）。ダイバーのライト点灯（円錐グラデが船体を掃く）。魚が舷窓から2匹出る | 船首→デッキ→マストを辿る MotionPath |
| S5 | .58–.68 | **新規 pinned セクション**（150vh） | 20m | **バディ**。二人目のダイバーが右から合流、並走、OK サイン（手パーツを1回転）。ここのコピーは「ひとりで潜って、ふたりで帰ってくる。」 | 並走 → 二人で少し上昇開始 |
| S6 | .68–.80 | gallery〜offers | 12m | **浮上開始**。カラーグレードが徐々に明るく（既存 grade を利用）。既存 offers（料金カード）はそのまま。※**ファンダイブは非掲載のまま維持。復活させないこと** | 右上へ緩やかに上昇 |
| S7 | .80–.92 | access〜trust | 5m | 泡が増え、水面の揺らぎ（ocean.js）が下りてくる | 上昇継続 |
| S8 | .92–1.0 | cta | 0m | **浮上**。水面を突き破る（白フラッシュ 200ms → 空の色）。コピー「浮上したとき、あなたは少しだけ、別の人になっている。」→ そのまま予約フォームへ視線誘導 | 画面上端へ抜けて退場 |

シーン章コピーの出し方: 各シーン開始 20% 地点で fade+blur in（既存 `[data-reveal]` の作法に合わせる）、終了 20% 手前で fade out。

## 5. 実装詳細

- すべて `ScrollTrigger` + `scrub: 1`。`pin` は S3/S4/S5 の新セクションのみ。`pinType` は Lenis と干渉しないよう既存 main.js の設定に従う。
- アニメは transform / opacity のみ。filter blur はテキストと霧だけ（面積の大きい要素に常時 filter をかけない）。
- 魚・サンゴ・船はすべてインライン SVG を `js/journey.js` から `<template>` 複製で生成。外部画像・ラスタ禁止（既存 assets/video は既存セクション用のまま）。
- 色は既存 CSS カスタムプロパティ（`--cyan`, `--sand`, `--ink-*` 系）を使う。新しい色を増やす場合は style.css の :root に定義してから使う。
- i18n: 新コピーは `js/i18n.js` の既存の仕組みに追加（現状2行の軽量ファイル。作法を読んで合わせる）。
- 既存の preloader / hold-to-dive / depth-meter / dive-profile(S5 既存実装) は**削除も変更もしない**。名前衝突に注意: この指示書のシーン番号と main.js 内の旧 S 番号コメントは別物。

## 6. パフォーマンス・アクセシビリティ

- `prefers-reduced-motion`: journey 全体を無効化し、各シーンのコピーだけ静的表示。pin もしない（既存 main.js の reduced 分岐と同じ流儀で）。
- GSAP CDN 失敗時: 既存の `hasGSAP` フォールバックに乗せ、journey は一切初期化しない。
- モバイル: パララックスレイヤーを 3→1 に削減、魚の数 60→24、pin 距離 200vh→140vh。`100vh` は使わず `dvh`。iOS Safari 実機相当（レスポンシブモード可）で確認。
- 60fps を目標。魚の反発計算は rAF 内で行い、ScrollTrigger の onUpdate では進行値の保存だけにする。
- Lighthouse: 追加 JS は journey.js 1ファイル（目安 <25KB minify 前）。

## 7. 受け入れ基準（全部満たすまで完了と言わない）

1. スクロールを止めるとアニメも止まり、逆スクロールで完全に巻き戻る（scrub の視覚確認）
2. S1〜S8 の出会いがすべて実装され、章コピーが表示される
3. 既存機能が全て生きている: hold-to-dive、depth meter、dive profile、予約フォーム、言語切替
4. 料金セクションにファンダイブが**表示されていない**（既存の非掲載を維持）
5. reduced-motion でジャーニーが安全に無効化される
6. モバイル幅(375px)で横スクロールが発生しない
7. コンソールエラー 0
8. 実ブラウザでフルスクロールのスクリーンショットを撮って確認（`npx serve` 等でローカル配信）

## 8. やらないこと

- 料金・プラン構成の変更（ファンダイブ復活は特に禁止）
- 既存セクションの HTML 構造の大規模書き換え（新規3セクション挿入と journeyStage 追加のみ）
- 音声の追加（過去に削除済み。戻さない）
- 外部画像・動画アセットの追加
